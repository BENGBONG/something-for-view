# 任务结果页：应用数据更新区域（评审增量）

## 分工与位置

中间结果区回答“本次交付了什么”，右侧工作台回答“具体内容是什么”。沿用用户提供的任务结果页结构，不调整左侧导航。

中间顺序：任务执行过程 → 交付产出物（有文件才显示）→ 应用数据更新（有实际更新时显示）→ 原有任务完成总结、评价及输入区。应用更新是独立的结果类型，不计入交付文件数量。既有评分与效率统计不属于本次新增需求。

## 中间卡片

一个实际更新的 App 一张横向卡片，不按 Agent 或数据表拆成多个应用。参照已有文件卡片，常规高度约 78px：左侧为图标、App 原名和已更新状态，第二行是一行新增/修改/删除摘要，右侧为两个查看入口。不再单独展示大数字统计区、数据表名称列表和提交时间行；数据表与提交时间在右侧工作台查看。

- 主操作“查看本次变更”：打开右侧工作台，选中“应用数据”、对应 App 和“本次变更”。
- 次操作“查看最新数据”：在同一工作台切到对应 App 的最新表格，不离开任务。
- 默认展示本次变更，避免把后续任务的数据当作本次结果。
- 计数来自同一次运行，不随最新数据改变；同一行两次修改算两次变更，不称为去重行数。
- 一次运行更新多个 App，各自展示和统计；仅绑定但没有更新的不列出。

## 右侧 AI Agent 工作台

保留“工具调用 / 文件列表 / 修订文件”，新增“应用数据”页签。应用数据不放入 output/tmp 文件树。

应用数据内按“选择 App → 本次变更/最新数据 → 切换数据表”组织：

1. 本次变更只列涉及的表，显示当前表的变更次数、记录名称、操作、修改前后值；删除记录仍能查看删除前内容。
2. 最新数据列出该 App 的可见表及最新记录，只读；提示其可能包含后续任务的更新。
3. 底部“在知识库中打开”是离开任务页的明确入口：本次变更定位到固定运行；最新数据进入对应 App。
4. 工作台关闭后，点击中间卡片重新打开并定位。更换 App 后重置到该 App 的有效数据表。
5. 没有最新数据权限时保留任务内有权查看的提交结果，不提供完整应用入口。

## 与文件交付的关系

文件和应用更新可同时存在，分别进入文件列表和应用数据。应用卡片不出现下载、另存、WPS 编辑。无文件的任务不为了占位而生成 XLSX；文件页签明确显示本次未生成文件。
